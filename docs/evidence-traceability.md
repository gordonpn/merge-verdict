# Evidence traceability and validation gaps

This investigation contributes to [issue 38](https://github.com/gordonpn/merge-verdict/issues/38). It inventories the requirements and decision rules at main revision `e307467`. It does not complete the broader specification wording audit or change policy. Requirements below describe intended behavior, not shipped behavior. The publishing-contract reconciliation in [PR 54](https://github.com/gordonpn/merge-verdict/pull/54) is separate; [AGENTS.md](AGENTS.md) remains authoritative while it is unmerged.

## Reading the matrix

Sources are repository-relative links. Each row groups related normative clauses; the requirement IDs and section numbers identify the original authority. A predicate is sufficient only when all required evidence is available and current. A schema accepting a value does not establish that GitHub supplied it or that an evaluator enforced it.

Freshness notation:

- **H**: review evidence must identify the current PR head SHA.
- **E**: CI and publication must identify the event evaluation SHA, including the synthetic SHA for merge groups.
- **B**: policy must come from the protected base revision, recorded as `policyVersion`.
- **R**: re-read mutable evidence before publication and compare the complete fingerprint with the initial capture.
- **Event**: respond to the relevant event, including activity on an unchanged head.

Actual coverage references use these labels:

- **Collector**: [collector tests](tests/collector/github-collector.test.ts) exercise mocked REST/GraphQL pagination, raw thread/comment/review/check/status metadata, base/head binding, supplied evaluation/policy SHAs, and typed errors. They do not test verdicts.
- **Retry**: [retry tests](tests/collector/retry.test.ts) exercise bounded delays, shared budgets, retryable responses, page recovery, and safe logging.
- **Models**: [model tests](tests/models) exercise schemas and normalized-record fingerprint determinism. [Snapshot tests](tests/models/snapshot.test.ts) cover order independence and selected mutations, not the complete raw-evidence pre-publication guard.
- **Config**: [configuration tests](tests/models/config.test.ts) cover defaults, normalization, parsing, mandatory gate enforcement, strict keys, and local file loading. Local default loading is not proof of protected-base API loading.
- **Gap**: no enforcement test exists at this revision. The implementation consists of collector, configuration, and model modules, plus the package smoke export. There is no evaluator, normalizer, runtime workflow, semantic engine, or publisher. Unmerged PRs, including 43 and 52, are not coverage.

## Auditing a future verdict

An auditable report must identify repository, PR, H, E, B and both snapshot digests; enumerate each required rule and its expected/observed evidence; link source records; and separate verdict from approval eligibility and merge-rule recognition. Missing evidence is visible as missing, not silently satisfied. Contradictory reviewers retain their individual records, and an active required-reviewer blocking decision cannot be erased by another reviewer's approval.

For example, all required CI may pass for H while a required reviewer reports an older SHA. The evidence is sufficient to explain PENDING, with expected H and observed reviewer SHA; it is insufficient to authorize approval. If a new top-level comment arrives before publication, the changed fingerprint instead makes that evaluation STALE. Neither example claims code correctness, and neither is currently an evaluator test.

The [commit-scoped approval proposal](docs/commit-scoped-approval.md) supplies additional proposed lifecycle/evidence fields. Its status remains a proposal; this inventory does not activate it. Completing issue 38 still requires cross-document wording reconciliation, resolved policy questions and concrete executable examples as the implementation workstreams land.
